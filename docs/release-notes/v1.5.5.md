## HornetDownloader v1.5.5 — 磁力续传（Resume check）

### 修正 / Fixes

- **磁力 / BitTorrent 正常退出再打开，不再看起来像从头下载。** 分块是否已经校验通过，记在数据目录 `%APPDATA%\HornetDownloader\bt\pieces\<infohash>.json`（不在下载目录放 bolt 数据库，避免 Windows 锁文件导致停在 0 速度）。正常退出再打开时，已完成的分块直接续传，不必整盘重哈希。
  *BitTorrent piece completion is now saved under the data directory. After a normal quit, completed pieces resume without a full rehash.*
- **文件被删短或改过时仍会校验。** 记录里的大小或修改时间对不上，相关分块会重新哈希；坏块不会被当成已完成。从 v1.5.4 升级后的第一次打开没有旧记录，可能仍要校验一次。
  *If a data file's size or modification time no longer matches the saved record, those pieces are hashed again. A same-size edit that does not change the timestamp is not detected.*
- **校验时界面写明是断点续传。** 列表状态为「校验续传」，说明为「正在校验已下载的数据（断点续传，不是重新下载）」。进度条保持上次进度，或显示校验进度，不会变成从 0% 开始的下载。任务详情同样使用这段说明。`/api/v1` 任务对象增加 `checking` 与 `resumeBytes`（只增字段）。
  *While that check runs, the list says it is verifying saved data for resume. New task JSON fields: `checking`, `resumeBytes`.*

仍使用 Go 1.26.10 构建（见 v1.5.3 说明）。Built with Go 1.26.10.

### 安装 / Install

```powershell
$f = "$env:TEMP\hd-install.ps1"; Invoke-WebRequest https://github.com/julius06117-cloud/HornetDownloader/releases/latest/download/install.ps1 -OutFile $f -UseBasicParsing
powershell -NoProfile -ExecutionPolicy Bypass -File $f -AddToPath -Json
```

Assets: `HornetDownloader-win64.zip`, `HornetDownloader.exe`, `hdl.exe`, `install.ps1`, `SHA256SUMS.txt`, `release.json`. Verify with `SHA256SUMS.txt`.
